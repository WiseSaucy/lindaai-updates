# Monthly Project Health Check

## Overview

Scores every active construction project Red / Yellow / Green across the metrics that actually predict whether the job lands on budget and on time: cost variance, schedule slip, billing health, change-order velocity, safety, and submittals/inspections. Outputs a one-page branded PDF Boss can hand to an owner or partner, plus a markdown copy for the brain. Run this monthly — or any time something feels off.

## When This Skill Applies

- User asks for a monthly project health check or scorecard
- User says "RAG report" or "red/yellow/green"
- User wants to know which jobs are in trouble
- User needs a one-page status for an owner, lender, or partner
- User says "review all my jobs"

## How It Works

### Step 0: License Check
Standard LindaAI license verification.

### Step 1: Pull Inputs Per Project

For each active project under `brain/projects/`, read:
- `budget.json` (variance, FAC vs. budget)
- `schedule.json` (slip days, milestone hit rate)
- `daily-reports/` (recent safety incidents, manpower trend)
- `change-orders/` (pending count, $ value)
- `submittals/` (overdue count)
- `billings/_log.md` (last billing date, current vs. earned)

### Step 2: Score Each Metric

Apply this matrix:

| Metric | Green | Yellow | Red |
|--------|-------|--------|-----|
| Cost variance (FAC vs budget) | within 1% under | 1–4% over | >4% over |
| Schedule slip | ≤5 days | 6–20 days | >20 days |
| Billing health | billed within 5 days of earned | 5–15 days lag | >15 days lag or underbilled >5% |
| Pending change orders | ≤2 / <$25K | 3–5 / $25–100K | >5 / >$100K |
| Safety (last 30 days) | zero incidents | 1 first-aid | recordable or near-miss |
| Submittals overdue | 0 | 1–3 | >3 |
| Inspection pass rate | 100% | 80–99% | <80% |

### Step 3: Roll Up to Project Score

- All Green or 1 Yellow → **Green** (on track)
- Up to 2 Yellow, 0 Red → **Yellow** (watch list)
- 3+ Yellow OR any Red → **Red** (intervention)

### Step 4: Trend Arrows

Compare against last month's archived health check (`brain/projects/health-archive/{YYYY-MM}.json`). Arrow per project:
- ↑ improving (one band up)
- → flat
- ↓ slipping (one band down)

### Step 5: Action Items

For each Yellow or Red project, generate 1–3 specific actions, e.g.:
- "Bill draw on Maple Ridge — underbilled $37,500"
- "Re-forecast Westside concrete code 03-300, projecting $12K over"
- "Chase 4 overdue submittals on Riverside — log via `/linda-submittal`"

### Step 6: Save & Render

Save:
- `brain/projects/health-check-{YYYY-MM-DD}.md`
- `brain/projects/health-archive/{YYYY-MM}.json`
- Branded PDF: `brain/projects/health-check-{YYYY-MM-DD}.pdf`

PDF brand requirements:
- **LindaAI** logo top-right
- **{customer_handle}** bottom-right
- Footer: `© 2024–2026 LindaAI — Built by Daniel Wise`
- Color-coded R/Y/G dots per row

## Example Usage

**User:** "Run the monthly health check."

**LindaAI:** "Let's gooooooo Boss — scoring 7 active projects." Reads all data, scores, writes markdown + PDF, replies with the table and top 3 actions. "Yeeee Hawww 🤠 — 4 green, 2 yellow, 1 red. Riverside needs a sit-down."

**User:** "PDF only, for the bank meeting tomorrow."

**LindaAI:** Renders just the PDF with the brand block.

## Voice & Tone

- Country, direct. **Boss**.
- Coach voice when calling out red projects — encouraging, not scolding.

## Error Handling

- **First time running (no archive to compare):** Skip trend arrows, note "First baseline — trend will appear next month."
- **Missing data on a project:** Score known metrics, mark missing as ⚪ with a note.
- **Render fails:** Save markdown anyway and tell Boss to print from there.
- **No license:** Country howdy and stop.
