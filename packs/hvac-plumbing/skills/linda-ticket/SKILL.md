# Service Ticket

## Overview

Builds the on-site service ticket the tech hands the customer at the end of the call: diagnosis, work performed, parts (with markup), labor, taxes, total, and a signature block. Renders a branded PDF the tech can email or text to the customer right from the truck. Pulls customer + job data straight from `/linda-dispatch` so the tech doesn't re-key anything.

## When This Skill Applies

- Tech finishes a service call and needs a customer-facing ticket
- User says "build the ticket for {job}" or "ticket for the Henderson call"
- User wants a printable / emailable work order
- User wants parts + labor + total with a signature line

## How It Works

### Step 0: License Check
Standard LindaAI license verification.

### Step 1: Pull the Job

Look up the dispatch record by `ticket_id` or by customer + date. Pre-fill customer info, address, equipment, problem statement.

### Step 2: Capture Service Findings

Tech provides:

| Field | Notes |
|-------|-------|
| Diagnosis | What was actually wrong |
| Cause | Why it happened (helps prevent recurrence) |
| Work performed | Bullet list of actions |
| Recommendations | Things customer should consider but didn't approve today |
| System status on departure | Operating normally / temporary fix / red-tagged |

### Step 3: Build the Bill

| Item | Schema |
|------|--------|
| Parts | name, qty, cost, markup, sell |
| Labor | hours × rate (plan members get plan rate) |
| Trip / diagnostic | flat fee (waived for plan members on covered systems) |
| Tax | per state |
| Discount | plan discount applied automatically |

Pricing rules from `brain/hvac-plumbing/pricing.json`:
```json
{
  "labor_rate_standard": 145,
  "labor_rate_silver": 130,
  "labor_rate_gold": 115,
  "diag_fee": 89,
  "parts_markup_default": 1.65,
  "tax_rate": 0.0625
}
```

### Step 4: Render the Ticket

Outputs:
- Markdown: `brain/hvac-plumbing/tickets/{ticket-id}.md`
- Branded PDF: `brain/hvac-plumbing/tickets/{ticket-id}.pdf`

PDF brand:
- **LindaAI** logo top-right
- **{customer_handle}** bottom-right
- Footer: `© 2024–2026 LindaAI — Built by Daniel Wise`
- Status badge top-left (Paid / Open / Quoted)

### Step 5: Capture Signature

Two paths:
- Print + customer signs paper, tech snaps photo, attach to ticket folder
- Email/text the PDF to the customer with a "reply YES to approve" instruction; LindaAI logs the reply as digital approval

### Step 6: Cross-Skill Hooks

- Parts used → reduce van stock via `/linda-parts`
- Equipment install → log warranty start via `/linda-warranty`
- Customer not on a maintenance plan → flag in summary "candidate for plan via `/linda-maintain`"
- Update dispatch record status to `complete` and total `${X}`

## Example Usage

**User:** "Build the ticket for Henderson — diagnosed bad run capacitor, replaced 45+5, recharged 2 lb R-410A, 1.5 hours labor. She's Gold."

**LindaAI:** "Let's gooooooo Boss." Pulls JOB-20260430-007, builds parts + labor with Gold rate, applies free diag, totals out, renders PDF + markdown. "Yeeee Hawww 🤠 — Ticket ready. Total $369.16. Want me to text it to her for digital sign-off?"

**User:** "Customer paid by card, mark paid."

**LindaAI:** Updates ticket status, sets badge to Paid, updates dispatch record.

## Voice & Tone

- Country, direct, **Boss**.
- Customer-facing copy: warm, professional, clear about what was done and why.

## Error Handling

- **No dispatch record:** Allow manual ticket — ask for customer + address.
- **Part not in catalog:** Add it on the fly with cost + markup, prompt to save to catalog.
- **Customer disputes total:** Save as `disputed`, do not auto-bill.
- **Signature missing on close:** Mark `pending-signature`, do not mark complete.
- **No license:** Country howdy and stop.
